Zombiefied Zombie Apocalypse - RimWorld 1.6 source port

Target build references:
- .NET Framework 4.7.2
- Krafs.Rimworld.Ref 1.6.4871
- Lib.Harmony 2.4.2

The stale pre-port Assemblies/Zombiefied.dll was intentionally removed.
Build the solution on Windows with Visual Studio/MSBuild so the resulting DLL is written to Assemblies/.

Suggested command from the project root:
msbuild Source\Zombiefied.sln /t:Restore,Build /p:Configuration=Debug

Port work includes the RimWorld 1.6 rendering, pawn tracker, pathing, logging,
collection, fire, pawn-generation, stat, RaceProperties, PawnKindDef, and CellRect API changes
reported by the supplied build log. The legacy synchronous path probing and custom wound overlay
call were removed because those internals changed substantially in 1.6.

Runtime render-tree fix:
- Zombie animal RaceProperties now inherit the source animal PawnRenderTreeDef, with an Animal fallback.
- The base zombie race now declares the Humanlike render tree so vanilla renderer entry points can initialize safely.
- Pawn_Zombiefied routes the legacy standard-zombie renderer through DynamicDrawPhaseAt for RimWorld 1.6's three-phase dynamic draw pipeline.

Runtime zombie-horde generation fix:
- Faction combat pawn-group generation may legally return an empty group at low threat points or for faction-specific group constraints.
- ZombieHorde now falls back to generic human source pawns when the faction group generator returns no pawns or throws.
- Source-to-zombie conversion is isolated from the source list, so a failed conversion cannot leave null entries that later reach GenSpawn.
- The notification targets the first successfully spawned zombie rather than assuming list[0] always spawned.

Outsider zombie avoidance
-------------------------
Foreign humanlike pawns now receive a RimWorld 1.6 PathRequest custom cost grid around spawned zombies.
The cost field extends fourteen cells from each zombie, overlaps up to a traversable maximum of 4,800, and
updates four times per second. The outer danger bands now begin at a meaningful cost so outsiders choose broad
detours before reaching a horde, while the stronger inner bands make cutting through a cluster extremely unattractive. Player pawns, zombies, animals, factionless pawns, and mechanoids are not
affected. Existing path customizers supplied by other mods are left untouched for compatibility.

Foreign humanlike pawns exclude zombies from the hostile-target cache and normal attack-target searches.
Sticky enemyTarget and meleeThreat references are cleared, direct Goto-nearest-hostile pursuit is rejected,
and proactive melee/static attack jobs against zombies are suppressed. This keeps zombies as pathing hazards
rather than secondary combat objectives while raiders, visitors, traders, and similar outsiders pursue their
original mission.

Runtime Harmony pathing fix:
- PathFinder.CreateRequest and PathFinder.FindPathNow prefixes bind original arguments by index, avoiding brittle parameter-name binding across RimWorld 1.6 builds.
- HugsLib was removed. Zombiefied now uses vanilla ModSettings, a GameComponent for lifecycle ticks, and an explicit Harmony.PatchAll call.

Runtime animal reanimation fix:
- Dynamically generated animal zombie races now inherit the source race's life expectancy, with the base zombie value as a safety fallback. This prevents PawnGenerator from producing invalid or immediately dead animal zombie candidates for races such as birds and livestock.
- Zombie ThingDefs are now reused when multiple PawnKindDefs share the same underlying animal race instead of constructing an empty replacement ThingDef for later pawn kinds.
- Reanimation first preserves corpse health conditions, then retries once without copied health conditions if that transfer makes the candidate invalid.
- Failed corpse reanimations are throttled to one retry per in-game day so an unsupported modded race cannot flood the log on every reanimation scan.
- Candidate generation now logs whether failure happened before or after source-data transfer, making remaining mod-race incompatibilities diagnosable from the player log.

Event-driven world integration
------------------------------
- Zombie caravan ambushes are registered as normal Caravan-target storyteller incidents. RimWorld's existing ambush machinery creates the temporary encounter map and moves the caravan into it.
- Zombie infestations are registered as a SitePartDef threat rather than as a permanent world-tile infection simulation.
- Vanilla quest/site systems may select the zombie infestation anywhere they request compatible threat tags, including item-stash, rescue, mineral-scanner, and generic active-threat sites. Rewards and objectives remain owned by the vanilla quest that selected the threat.
- Zombie infestation site parts are deliberately factionless so world sites do not claim that an unrelated pirate or tribal faction owns the zombies.
- Both world-site zombie threats and caravan zombie encounters can be enabled or disabled independently in the native mod settings.
